# 软件测试计划 — 修仙包

简体中文 · [English](STP.md)

状态：草稿。
批次：B12
日期：2026-11-10

需求在 `SRS.md`；下面每个测试说明它覆盖什么、什么算通过。本仓没有测试运行器：
一个测试是一段维护者能走完的流程——用 `infra/` 里的工具，需要引擎时用网页版。
步骤在 `STD.md`。

测试按它们保护的东西分组，而不是按运行时机分组：先身份与信封，因为其余都骑在一个
合法压缩包上；再语言，因为那里的遗漏在安装时就是致命的；然后玩法；最后发布。

## 测试

| Test | 覆盖 | 出口判据 |
|---|---|---|
| `TC-ID-001` | `REQ-001` | 逐目录构建各出一个压缩包，且每个包的 `manifest.id` 等于其目录名。 |
| `TC-ENV-001` | `REQ-002` | `check_pack.py` 接受两个压缩包；一份带第二个根文件、符号链接或超过 8 MiB 条目的副本被拒并给出理由。 |
| `TC-IDN-001` | `REQ-003` | 切换界面语言时显示名在「修仙」与 Cultivation 之间变化，且包列表上不出现 id。 |
| `TC-LOC-001` | `REQ-004` | 两个包的每个节点 id 与每个标签键都有英文；删掉其中任意一条都会让安装失败。 |
| `TC-LIN-001` | `REQ-005` | 线性包走五个节点后到结束屏；派遣包的山门节点显示动作而不是结束。 |
| `TC-PRG-001` | `REQ-006` | 线性包的步数随节点递增，且它的规则文件声明零条规则。 |
| `TC-BLF-001` | `REQ-007` | 两次回答相反的局落在不同结局，且记录的信念数不同。 |
| `TC-VOI-001` | `REQ-008` | 四场心声戏在没有听者选项时走不到，有时走得到。 |
| `TC-DSP-001` | `REQ-009` | 每次派遣至少改变一个弟子键；伤为 2 的弟子被拒，理由里点出该键。 |
| `TC-DSP-002` | `REQ-009` | 一次歇息让受伤的弟子重新可派，下一次派遣成功。 |
| `TC-PHS-001` | `REQ-010` | 三十六个动作耗尽天数；伤到 3 时本局以该弟子自己的失败语结束。 |
| `TC-PHS-002` | `REQ-010` | 开门后中枢仍给动作，开局天数显示 36。 |
| `TC-ECO-001` | `REQ-015` | 一级田让此后每个动作多一石；跨过第 12 天的那个动作翻年，并扣一石存粮。 |
| `TC-ECO-002` | `REQ-015` | 进入第二年时墙不足六级，本局以那一年的破墙语结束；六级则继续。 |
| `TC-ECO-003` | `REQ-015` | 第一年之后某天开局米缸为零，本局以米缸语结束，而不是伤。 |
| `TC-SAV-001` | `REQ-011` | 存档只出现在它自己的包里，读回时节点与账本数值与存档时一致。 |
| `TC-COL-001` | `REQ-012` | 两个包出现在同一个世界条目下；删掉合集块后其中一个被单独列出。 |
| `TC-REL-001` | `REQ-013` | 对任一已发布标签，下载压缩包求哈希，与描述文件里的 sha256 一致。 |
| `TC-CI-001` | `REQ-014` | 弄坏某个包的提交让工作流转红；当前 main 是绿的。 |

## 这里不测什么

引擎自己的行为——怎么画一个节点、怎么合并译文、怎么算步数——在 `lethebar` 里测。
这些测试只查包带上了引擎需要的数据，以及玩家能看出差别。
